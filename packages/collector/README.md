# Collector

This package is the public, auditable half of the product (PRD §6, decision 2). It contains everything that touches your data before it leaves your machine: the collectors that read local AI-session stores (Claude Code today; Cursor and Codex CLI to come) and git metadata, the redaction pipeline that strips secrets and raw text, and the full scoring methodology — signal definitions, criteria, and weights. It is published under Apache-2.0 and mirrored to a public repository as an explicit allowlist, so you can verify exactly what is computed and what is (and is never) transmitted.

The scoring engine (`src/scoring/`) is pure, deterministic, and clock-free: it consumes the normalized event stream and returns a Builder Profile — three 0–100 scores (AI Collaboration with four named sub-signals, Testing Discipline, Shipping Momentum), a rule-based Builder Type, and strengths/weaknesses/focus — with byte-identical output for byte-identical input ("now" is always the stream's own max timestamp, never the wall clock). Every formula, weight, threshold, and confidence rule lives in `src/scoring/weights.ts`; the table-driven test fixtures next to each rule are the methodology documentation. Every number carries structured evidence only — statistic kinds, numerators/denominators, and references to your own sessions and commits — never prose; thin data is labeled low-confidence and absent data scores null, not zero. The git collector additionally emits a `churn_snapshot`: aggregate counts of lines added and lines rewritten/deleted within a 14-day window — counts only, never paths, hashes, or messages.

The redaction pipeline (`src/redaction/`) is rule-based and deterministic: an ordered, fully visible table of regex rules — secret patterns derived from [gitleaks](https://github.com/gitleaks/gitleaks) (MIT) plus rules for emails, absolute home paths, env values, and credential-bearing URLs from the PRD §9 data-handling contract — applied by a pure engine whose findings carry rule ids and counts only, never matched text. Its release gate is the secrets-corpus suite, which any auditor can run (`pnpm vitest run --project @cosquared/collector -t "secrets corpus"`): a seeded corpus of fake but format-valid secrets that must be caught at 100% with zero survivals, plus a benign corpus that must produce zero false positives.

What will never live here: the coaching engine and its prompts, the recommendation library, benchmark and goal-outcome data, and the skill graph. Those are the private half of the product. This package depends only on `@cosquared/schema` (the public telemetry schema) — it has no dependency on any private package, and collectors receive filesystem paths as parameters rather than reading product configuration.
